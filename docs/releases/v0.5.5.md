# Cloud Mounter 0.5.5

Prepared October 22, 2026; not published. Release metadata and change descriptions
are finalized for package preparation. Scoped native acceptance is recorded;
final 0.5.5 Debian/Flatpak package acceptance and publication remain pending.

## Legacy OneDrive engine retirement

OneDrive Online remains supported through onedriver, and Offline mirrors through
rclone bisync. The abraunegg/onedrive engine, authentication handoff and executable
route are removed. Dependency setup no longer installs it; existing packages are
not uninstalled. Python remains a build/developer dependency.

Old profiles remain visible and removable without being converted. Their mirror,
recovery, database and credential files are preserved. On runtime-owner startup,
verified app-owned legacy monitor units are disabled and stopped through systemd
D-Bus. The unit file is removed only after confirmed inactivity. Unverified units
are left untouched; failed retirement is reported and never rolls back by
restarting the retired engine.

Before replacement, confirm that the legacy monitor has stopped and preserve
unsynchronized files. Create a new rclone connection with separate mirror and
recovery folders and new authentication. Run Preview and the confirmed initial
Sync Now; verify your files before removing the old connection. Do not copy
legacy databases or credentials into rclone.

See [dependency guidance](../dependency-installation.md). Published
[0.5.4 notes](v0.5.4.md) remain the transition-release history.

## Connection setup and interface

Add and Modify use consistent action ordering and shared button states: blue for
recommended actions, grey for secondary actions, red for removal, with faded
buttons and progress labels while blocked or running. Shared-remote saves show
Confirm Save before the second click. Settings lists rclone remotes with aligned
actions and permits removing unused remotes.

Google Drive and Box fresh setup now starts browser authentication and verifies
access before reporting success. Existing OneDrive rclone remotes can be verified
and fully tested in one Test action. Settings reconnects when the panel applet
restarts, and retired profiles with absent units no longer invalidate unrelated
status observations.

## Browsing and mirrors

Google Drive mounts enable fast-list at mount creation and refresh the root
before recursive directory preload. Using your own Google OAuth client ID and
secret is recommended in the setup window.

Box/Google root mirrors exclude their recovery directory from synchronization.
SharePoint mirrors support a whole document library as well as a selected
subfolder. These root/library paths have narrower live validation than subfolder
mirrors, as described below.

Failed mirror commands show bounded redacted diagnostics. A failed Preview keeps
a stopped schedule's toggle off and offers Repair. Offline settings label the
sync interval explicitly in minutes.

## Installation and compatibility

Planned GitHub artifacts are Debian packages for Ubuntu 22.04, 24.04 and 26.04
(amd64/arm64), plus Flatpak bundles for x86_64 and aarch64. These targets remain
subject to the final build and acceptance results. COSMIC repository availability
requires a later PR and maintainer review.

Storage engines run on the host: rclone >= 1.74.3 for rclone mounts/mirrors,
onedriver >= 0.15.0 for OneDrive Online, and FUSE3 for mounts. NetworkManager and
the applicable VPN components are installed separately. No legacy onedrive
engine is required by 0.5.5. See the [dependency guide](../dependency-installation.md)
and [installation instructions](../../README.md#installation).

## Validation and known limits

Native development installations have accepted legacy-unit retirement and data
preservation, the guided GUI/button checks, Settings reconnection, and selected
Google Drive/Box mount and subfolder-mirror flows. These observations establish
only their recorded scope; automated and local-engine tests do not establish
all provider paths or final-package acceptance. See the
[acceptance matrix](../../Task%20List%20Completion%20Notes.md#055-acceptance-reconciliation-october-22-2026).

Package-specific upgrade acceptance includes retained retired-profile handling
and the missing-retired-unit status regression. Remaining checks are tracked in
the [task list](../../Task%20List.md).
Google Drive and Box whole-account mirrors have not been exercised against live
cloud accounts because of their size. Root/recovery handling has local-engine
test coverage; installed cloud mirror checks used selected subfolders.
SharePoint whole-library selection is implemented, but installed whole-library
acceptance remains open; the accepted cloud test used an archive subfolder.
Final-package sandbox authentication, worker/portal access and upgrade checks
remain separate from native observations. No new Debian or Flatpak build/install
is implied by the accepted native installations. COSMIC repository PR and
maintainer approval come later.
