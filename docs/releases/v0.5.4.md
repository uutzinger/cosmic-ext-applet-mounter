# Cloud Mounter 0.5.4

Published October 20, 2026. [GitHub release](https://github.com/uutzinger/cosmic-ext-applet-mounter/releases/tag/v0.5.4).
Release tag v0.5.4 resolves to source aa25846c6558a72a6fb1602aab83fc3997495e91.
All ten public asset digests match the verified publication receipt.

## Changes

- New personal and work/school OneDrive Offline mirrors use rclone bisync,
  with Preview, confirmed initial Sync Now and a 15-minute default schedule.
  Save leaves scheduling paused; Start enables it explicitly.
- Existing abraunegg/onedrive mirrors remain supported for this transition
  release, with deprecation and manual replacement guidance. New mirrors cannot
  select that engine. OneDrive Online continues to use onedriver.
- The WebKit sign-in helper and its helper-only GUI dependencies are removed.
  Existing legacy mirrors retain browser/manual response-URL reauthentication;
  saved credentials and normal synchronization are preserved. No host libraries
  are automatically uninstalled.
- Flatpak mirror and recovery directories use separate Browse authorizations.
  Recovery guidance now explains that requirement. Repair is available after a
  failed manual synchronization even when the schedule is paused.
- Saving a disabled mirror explains the Enable → Test Connection → Save
  sequence. Enabling and saving does not start background synchronization.
- VPN-bound Save checks VPN readiness before persistence. Canceled
  authentication leaves the previous saved settings unchanged.

## Installation and compatibility

GitHub distribution targets Debian packages for Ubuntu 22.04, 24.04 and 26.04
(amd64/arm64), plus standalone Flatpak bundles for x86_64 and aarch64.
The release installer scripts select the OS/CPU where applicable and verify
checksums before installation. The Flatpak installer sets up the user runtime;
install Flatpak through your distribution first. Bundles require manual updates.
See the [README installation instructions](../../README.md#installation).

Storage engines and VPN components run on the host and need separate setup.
New OneDrive mirrors require rclone >= 1.74.3. OneDrive Online uses onedriver;
retained legacy mirrors still need abraunegg/onedrive. See the
[dependency guide](../dependency-installation.md).

Native and Flatpak editions share saved connections and host services. Pause
connections, close windows and remove the panel applet before switching editions;
run one edition at a time. If both are installed, the panel picker can show two
Cloud Mounter entries. `flatpak ps --columns=application` identifies a running
Flatpak instance.

There is no automatic conversion of legacy mirrors. Full legacy-engine removal,
GUI cleanup and COSMIC Flatpak repository submission are planned for 0.5.5.
GitHub distribution does not imply COSMIC repository approval. Do not uninstall
legacy dependencies while an existing mirror still needs them.

## Replace an existing legacy mirror manually

1. Open the old connection and record its account, selected OneDrive folder and
   local mirror location. Pause it and wait for any active sync to finish. Keep
   it paused throughout replacement.
2. Preserve the old local mirror and recovery directory. Copy any local changes
   that have not reached OneDrive to a separate safe location; a fresh mirror
   downloaded from OneDrive cannot recover files that were never uploaded.
3. Use **Add Connection → OneDrive → Offline mirror**. Select personal or
   work/school, enter the expected account and connect a new rclone remote through
   Microsoft sign-in. An already verified rclone remote for that same account may
   also be selected. Do not copy the legacy token, database, configuration or
   cache into the new connection.
4. Select the same intended OneDrive folder. Choose a **new, separate local
   mirror** and **separate recovery directory**, outside the old mirror and its
   recovery tree. Equal, parent and child overlaps are blocked even when the old
   connection is paused or disabled. In Flatpak, authorize each local directory
   with its own **Browse** button; typing a host path does not grant access.
5. Verify the selected remote, run **Test Connection**, and save. The new mirror
   stays paused. Run **Preview**, then **Sync Now** and confirm initial sync.
   Check its completion and inspect the files before enabling scheduled sync.
6. Compare the new mirror with the old local files and your separate copy of
   unsynchronized work. Resolve differences deliberately. If needed, copy only
   user files into the new mirror and use Preview/Sync Now again; do not copy
   ownership markers, synchronization state, databases, caches or credentials.
7. Once the replacement is verified, use **Remove** on the old Cloud Mounter
   connection and confirm removal. Removing a connection removes its managed
   units and saved entry; local mirror/recovery files are preserved. Do not delete
   the old mirror's contents while it is connected and syncing: deletions could
   propagate to OneDrive. Deleting OneDrive folders is not part of replacement.
8. Start scheduled sync only for the verified replacement. Retained old local
   files and credentials can be reviewed and cleaned up separately by the user;
   phase-5 deprecation does not delete them.

## Verification and known limitations

Installed development checks covered personal and work/school OneDrive mirrors,
SharePoint folder access, synchronization safeguards, Repair, scheduled/manual
sync, idle sleep/wake and manual VPN authentication. Native Debian testing on
Pop!_OS 24.04 amd64 covered personal/work mirrors and onedriver Online mounts.
The hosted x86_64 Flatpak passed checksum verification, installed-commit
readback and panel/settings/connection-editor smoke on the existing VM.
Unchanged provider, VPN and mirror results are reused; detailed identities and
coverage are in the [acceptance map](../engineering/release-054-acceptance-audit.md).

The aarch64 Flatpak passed build and offline verification; installation on ARM
hardware was not tested. A separate clean-profile Flatpak check was deliberately
omitted in favor of the completed fresh-VM Debian and existing-VM Flatpak checks.
All ten public GitHub assets were downloaded and checksum-verified after
publication; both README installer URLs matched source and passed shell syntax
checks. No additional installation was performed for that download check.

Additional legacy reauthentication/monitor/transfer tests were deliberately
skipped. Active-transfer sleep/VPN-loss, scheduled VPN-unavailable and live
shared/pre-existing VPN ownership variants were not newly tested. These limits
are retained explicitly; automated tests do not replace installed live evidence.

Offline mirrors do not coordinate simultaneous multi-user document editing.
Preserve unsynchronized local work before replacing any mirror. Review the
[OneDrive mirror contract](../engineering/onedrive-rclone-offline-contracts.md)
for supported primary-drive scope and safety requirements.
