# Cloud Mounter 0.5.4

Status: Draft — not released. This records the agreed OneDrive migration scope;
final package, platform and release acceptance remain pending. It is not a
complete release changelog or publication announcement.

## OneDrive offline mirrors

New OneDrive Offline connections use rclone bisync, for personal and work/school
accounts. Synchronization is scheduled, with manual Preview and Sync Now.
OneDrive Online mounts continue to use onedriver.

Existing Offline connections using abraunegg/onedrive remain supported in 0.5.4.
Their Modify window explains the deprecation and manual replacement process.
They retain their engine and existing authentication; there is no automatic
conversion. New connections cannot select the legacy engine.

Removal of the legacy engine, its authentication helper and dependencies belongs
to the release after 0.5.4, tentatively 0.5.5. That removal has not shipped in
0.5.4. Do not uninstall legacy dependencies while an existing mirror needs them.

## Replace an existing legacy mirror manually

1. Open the old connection and record its account, selected OneDrive folder and
   local mirror location. Pause it and wait for any active sync to finish. Keep
   it paused throughout replacement.
2. Preserve the old local mirror and recovery directory. Copy any local changes
   that have not reached OneDrive to a separate safe location; a fresh mirror
   downloaded from OneDrive cannot recover files that were never uploaded.
3. Use **Add Connection → OneDrive → Offline mirror**. Select personal or
   work/school, enter the expected account and connect a new rclone remote through
   Microsoft sign-in. An already verified rclone remote for that same account may
   also be selected. Do not copy the legacy token, database, configuration or
   cache into the new connection.
4. Select the same intended OneDrive folder. Choose a **new, separate local
   mirror** and **separate recovery directory**, outside the old mirror and its
   recovery tree. Equal, parent and child overlaps are blocked even when the old
   connection is paused or disabled. In Flatpak, authorize each local directory
   with its own **Browse** button; typing a host path does not grant access.
5. Verify the selected remote, run **Test Connection**, and save. The new mirror
   stays paused. Run **Preview**, then **Sync Now** and confirm initial sync.
   Check its completion and inspect the files before enabling scheduled sync.
6. Compare the new mirror with the old local files and your separate copy of
   unsynchronized work. Resolve differences deliberately. If needed, copy only
   user files into the new mirror and use Preview/Sync Now again; do not copy
   ownership markers, synchronization state, databases, caches or credentials.
7. Once the replacement is verified, use **Remove** on the old Cloud Mounter
   connection and confirm removal. Removing a connection removes its managed
   units and saved entry; local mirror/recovery files are preserved. Do not delete
   the old mirror's contents while it is connected and syncing: deletions could
   propagate to OneDrive. Deleting OneDrive folders is not part of replacement.
8. Start scheduled sync only for the verified replacement. Retained old local
   files and credentials can be reviewed and cleaned up separately by the user;
   phase-5 deprecation does not delete them.

## Dependencies and acceptance boundaries

New mirrors require rclone >= 1.74.3. Live OneDrive prototype evidence used 1.75.0;
the minimum-version assessment is source-based. See the
[dependency guide](../dependency-installation.md) and
[OneDrive mirror contract](../engineering/onedrive-rclone-offline-contracts.md).

Installed development Flatpak smoke covers both OneDrive account flows, personal
manual/scheduled/restart/Pause/recovery, corporate initial transfer, SharePoint
shared folder access, and preservation on disposable connection removal. The
legacy deprecation notice and existing onedriver Online mount/list/unmount were
reviewed in the installed applet. Legacy Preview worked; actual legacy monitor
and transfer acceptance remains pending on separate disposable resources.

Further installed personal smoke verified identity/target/ownership-marker
refusals, Repair with preserved mirror/recovery/bisync state, normal sync after
Repair, idle sleep/wake followed by checksum-verified sync, and manual OpenConnect
VPN authentication cancellation, positive authentication, bound sync and optional
release of an applet-activated tunnel. A popup defect that hid Repair after a
failed manual sync with a paused timer was fixed and the replacement tested.

These checks establish the scoped phase-6 Flatpak migration smoke. They do not
establish release-wide native/Debian/Flatpak acceptance, active-transfer sleep or
VPN-loss behavior, scheduled VPN-unavailable behavior, or live pre-existing/shared
VPN ownership protection. Those final acceptance gates remain open. Existing
source/fake-adapter tests are recorded separately from installed evidence.

Both local directories in Flatpak must be selected with their own Browse buttons;
the recovery field no longer promises automatic selection. VPN-bound OneDrive
Save validates VPN readiness before persistence and may open authentication;
cancelling authentication blocks Save and retains the previous saved settings.

Final supported package/platform scope, release metadata and checksums will be
filled in after release acceptance. These notes remain a draft; no 0.5.4
publication or store submission is claimed.
